# 多年度财务研究修复

2026-10-11，v0.7.1，业务数据库 schema 4。

## 原因与改动

用户报告“多个会计年度只有单一年度，无法重复请求，所以工具无法支持”。只读核对该运行后确认：财务请求为年报利润表、limit=4，原始证据已经返回 2022、2023、2024、2025 四期且质量为 available。报告生成器对财务响应选取最新一行，其余三期没有进入核验事实；综合模型只能看到最新期，错误地认为需要重复取数。

- 新运行逐期生成财务事实，保留报告期末、会计年度、年度口径、币种、报表类型、供应商披露时间及准确的原字段索引。事实排序不改变原始响应的行号。
- 多年度目标带 required_periods；满足目标需要同一标的、币种、报表与年度口径下，各必需字段共同覆盖所需的不同报告期。只引用最新年、某年度必需字段为空或重复同一期都不能通过。
- 已有历史事实优先复用。真实数据不足时，可以追加更大的 limit 或新的日期范围；完全相同的请求仍受幂等约束，原追加次数与预算限制保留。
- 财务表及 Markdown、HTML、CSV 保留各年度。点击旧年度依据显示该年度的报告期、披露日期与原字段值。
- 财务事实文字从原始报告期毫秒时间戳转换为上海日历日期，避免直接截取 UTC 日期而提前一天；内部 ISO 时点与原始毫秒值仍保留。
- 修正中文数值校验误把“披露时点元数据”中的“点元”识别为金额的问题；中文百分比、金额、倍数与阿拉伯数字仍受校验。
- “目标尚无可用工具”改为准确的未完成/支持范围提示；模型指令要求不重复列出同一目标缺口。

新运行固定 financial_history_version=1，生成报告 schema 3。此前运行仍使用其原报告规则/schema 2，避免改变既有事实编号、指纹、引用或导出。没有修改用户默认数据库、配置或历史报告；更新后需要重新提交研究目标。

主要实现：`server/harness/reporting.py`、`dialogue.py`、`runtime.py`、`server/ui/workbench.py`、`presentation.py`。年度方向观察仍是有来源的模型解释；没有新增单股同比/复合增长率公式，也没有核验公告原文或业务归因。供应商披露字段不等同于已核对交易所公告日期。

## 验证

针对多年度和原核心能力：32 passed，263.66 秒。新增 12 项覆盖四期进入模型/表格/导出/精确来源、只引最新年的拒绝与修正、limit=1 扩大到 4 后完成、年度必需字段为空、旧报告兼容、披露元数据正常表述、中文小数及百分比拦截，以及不将 2020 年误识别为二十期。构造测试与真实供应商结果分别记录。

真实模型与扶摇：25 项检查通过。目标为茅台最近四个已披露年报的营收/归母净利润及最近六十交易日的前复权价格变化、波动率、最大回撤。结果 completed / complete / validation passed、无目标缺口，四个年度均可见，八个核心财务值分别回查原字段，四类导出通过。模型三次（规划含一次有界修正）、工具四次，其中财务请求仅一次。完整市场响应及 Cookie 位于忽略的独立缓存，公开记录不复制这些内容。

真实 Edge/Playwright 复用上述结果，17 项检查通过：四期表格、最早年度原字段/报告期/披露日期、综合依据按钮、四类实际下载与年度保留、390px 无横向溢出、账本无新增调用、零未捕获页面错误。桌面和手机截图已查看；财务表及原字段另由快照和交互检查确认。

保留初次失败：真实综合回答的“时点元数据”误触发数值规则，修正轮返回非法 JSON；修正匹配规则后真实复验通过。首次针对性回归为 17 passed / 8 failed：八项轮询在八秒内超时，事件记录显示随后完成；改为二十秒的有限轮询后 32 passed，真实终态、调用次数及原业务约束仍检查。首次浏览器原字段操作超时，快照显示连接中断；重启隔离实例并加入所选期间显示后，完整交互通过，没有据此移除原字段检查。

全量回归 155 passed，576.29 秒（`financial-history-final.xml`）。最后修正报告期文字的上海日期后，最终财务文件另做 12 passed，28.14 秒（`financial-history-date-final.xml`）。此前 32 项针对性结果保留，合计是 155 个不同用例，不将重复复验累加为新用例。

最终日期规则上再做真实模型/扶摇复验，26 项检查通过（含上海报告期文字），结果仍为完整四年度研究；模型两次、工具四次、财务请求一次。前一轮 25 项/三次模型结果保留为该轮实际情况。最终生产代码编译通过，pip check 无冲突，HTTP/API/OpenAPI/Socket.IO 冒烟通过；84 个拟公开文本文件配置密钥、私有文件和忽略规则扫描通过。本记录不把早先 v0.7.0 的验证替代本次多年度验证。

最终四年度真实结果再次通过 17 项浏览器检查，财务表截图也已查看；没有新发模型或金融请求。元数据汇总为被忽略的 `docs/verification/financial-history-finish.local.json`。本轮隔离服务与浏览器已关闭，8108 端口确认无监听；用户原服务没有停止。

## 复验

停止 PyCharm 中的旧运行，用原 `.venv`、模块 `server.main` 和项目根目录重新启动，刷新页面，提交上述多年度目标。既有报告保持历史结果；新运行应显示各年数据及对应依据。供应商真实缺期、口径不一致或必需字段为空时，仍按具体缺口输出。

```powershell
& .\.venv\Scripts\python.exe -m pytest tests -q
& .\.venv\Scripts\python.exe scripts\verify_financial_history_live.py
```

第二个脚本调用本机已配置的真实模型与扶摇，使用独立缓存，可能消耗配额。浏览器脚本 `scripts/verify_financial_history_browser.cjs` 检查保存的真实结果，不新发供应商请求；需在对应缓存数据库上启动隔离服务并配置本机 Playwright/Edge 路径。
