# Agent 基础能力复核与补齐计划

日期：2026-10-11。依据：原题、用户实际反馈、源代码和本地运行账本。本文件保留修复前的诊断与 A–C 要求；本轮已实现核心修复，最新行为、测试及真实验证见 [核心修复记录](agent-core-readiness.md)。

## 修复前的完成状态修正

当前已建立工具、证据、确定性计算、运行控制、上下文、长期记忆和检查点恢复的底座，并通过已有范围内的本地检查。研究 Agent 的意图理解、澄清交互、结果观察、目标完成判断和综合回答尚未形成完整闭环，因此不能将第 1–6 批的阶段检查通过等同于产品能力完整。

原题明确要求目标驱动的任务规划、金融工具、上下文与长期状态、可验证成果、必要确认及完整投资产品体验。普通问答、澄清和目标完成检查是实现这些能力的必要产品设计，不能全部塞入取数计划。它们并非原题逐字列出的模块名称；用户本轮也明确要求补齐 Agent 的基本能力。按用户此前说明，不以题目中的 24 小时限制实施。

## 修复前的现状与缺口

| 能力 | 当前实现 | 必须补齐的行为 |
| --- | --- | --- |
| 理解请求、选择处理方式 | 所有自动请求直接进入 JSON Planner | 区分一般解释、需要澄清的研究、可执行研究、追问及能力边界 |
| 普通投资问答 | Plan 必须有工具任务，报告必须有量化事实 | 方法论和概念问题允许直接回答，标明一般知识，不冒充当前数据研究 |
| 澄清与标的消歧 | 可记录 unresolved_goals；名称不唯一会拒绝下游 | 保存待回答问题，用户补充后继续；缺参数与预算审批分别处理 |
| 规划与工具执行 | 结构化计划、依赖校验、白名单和真实工具已实现 | 计划包含研究目标的分项验收条件；支持单只股票研究，不限定为两家公司比较 |
| 观察结果与调整计划 | 执行后保存上下文；任务失败时最多一次追加替代计划 | 将经校验的字段、指标、覆盖范围与缺口交给模型；工具成功但目标未覆盖也能触发补充工作 |

| 综合研究与自然语言回答 | 核心数字由代码生成；解释主要为固定模板 | 模型基于有效证据解释研究结果，引用事实，区分推断和不确定；数值仍由代码校验 |
| 多轮上下文 | 关联追问创建新 Run，旧报告和记忆可进入上下文 | 同一研究空间保存用户与助手消息，理解省略对象、研究范围更改和澄清答复 |
| 失败解释与恢复 | 已有有界重试、账本、控制和恢复；部分错误合并 | 区分接口失败、JSON 无效、计划不合法、缺少输入、没有可用数据和回答校验失败 |
| 预算、权限、持久化与可追溯 | 已有真实实现和测试 | 所有新增模型阶段、等待输入、产物和恢复同样遵守这些约束 |

## 实际问题与代码依据

用户反馈的“怎么研究股票”运行中，模型两次返回了 JSON，识别出方法论问题且没有安排取数任务。`planning.validate_plan` 拒绝空任务，`runtime.model_plan` 将本地校验失败与接口失败合并记录；最终没有工具和数值证据，`reporting.build_report` 生成统一缺口模板。请求本身合理，问题发生在应用的处理路径。

原实现方案第 8.2 节已经规划模型生成带证据的 Claim，实际 `runtime.report` 只调用确定性报告生成器。证据目录提供质量、时点、记录数和读取 URL，计算目录提供引用与方法；当前规划协议没有让模型按需读取证据字段并完成综合回答的动作。保存了上下文不等同于模型已经利用结果开展分析。

`runtime.gate` 在任务失败或被阻断时尝试有限重规划，任务都完成后进入报告。它没有独立检查目标的分项是否被满足。只查到交易日历也可能完成一个合法任务，但并不能回答股票研究目标。

此前 123 项检查和真实集成结果仍只证明记录的范围，不能作为上述未实现能力的通过证据。问题来自规划范围、实现取舍和验收标准三处，不能只修改错误提示或添加一个问答按钮后继续宣称完成。

## 补齐顺序

### A：请求理解、问答和澄清

1. 在自动研究入口增加有结构化输出的请求理解阶段，并接入已有模型账本、预算、上下文和恢复机制。
2. 一般解释直接输出助手回答，允许零工具调用；不因没有量化结论标记为研究失败。
3. 需要标的、范围或消歧时生成简短问题与可选项，持久化等待输入状态。用户回答后继续同一目标，不让用户重新填写全部研究。
4. 明确请求不必重复确认；可采用的默认口径应显示。涉及研究范围或预算扩大再请求相应确认。
5. 保存线程内消息，将普通追问、澄清答复和新增研究分别关联到正确的状态。

阶段出口：在实际浏览器中，“怎么研究股票”得到方法论回答；“帮我研究一只股票”进入澄清；回答标的后继续；刷新仍能看到消息和待回答问题。

### B：观察、目标检查和综合回答

1. 将目标拆成有限、可检查的研究分项，记录所需证据、支持的能力和无法覆盖的部分。
2. 使用已有字段与公式校验生成模型可读的证据摘要，包含数值、单位、时点、口径、引用和缺口；原始大响应仍保存在服务端。
3. 在适当阶段观察结果并检查目标覆盖。工具调用成功而证据不足时，可以提出补取、修改可用方案或询问用户。
4. 有限重规划、报告修正及澄清后继续均遵守模型次数、token、工具次数和总时限；避免循环和重复派发。
5. 增加基于证据的综合回答。事实引用及数字由代码验证，推断必须有依据和适当限定；无法查证的原因不能写成确定事实。
6. 对核心数值校验失败的结论要求有界修正或阻止发布。保留已有有效材料时输出具体部分成果；完全没有研究成果时明确失败原因。
7. 合法的知识回答、等待输入、研究部分完成、执行失败、模型回答校验失败分别呈现，不统一转换成“尚无可验证结论”。

阶段出口：单只股票与两只股票比较都能完成受支持范围的研究；回答对应用户问题并可回到依据；不足的维度明确说明；成功取数但缺少所需指标的场景能被目标检查发现。

### C：按用户任务重新验收

| 输入或故障 | 必须看到的行为 |
| --- | --- |
| “怎么研究股票” | 方法论回答，无需任意取数，不产生无数值缺口 |
| “帮我研究一只股票” | 询问必要标的信息，回答后继续 |
| “研究贵州茅台” | 解析标的，采用并展示合理默认范围，产出单股研究 |
| 同名或多个候选标的 | 请求选择，不猜测，不重新派发已经完成的解析 |
| 明确代码和范围的比较研究 | 无多余澄清，真实工具、数值、来源与综合解释一致 |
| “它和另一家公司比呢” | 继承正确对象与约束，新增需要的证据 |
| “只看近 30 个交易日” | 明确范围变更，并使新结果对应新口径 |
| 工具成功但字段为空、覆盖不足 | 不误判目标完成，补充工作或准确说明缺口 |
| 无数据权限或模型超时 | 展示具体原因及可行恢复方式，保留已完成工作 |
| 模型生成虚构数字或错误引用 | 检出并有界修正，失败部分不作为已验证结论 |
| 请求确定性预测或直接买卖指令 | 说明研究边界，提供可执行的事实研究方向 |
| 澄清、观察、综合回答期间重启或停止 | 恢复真实状态或停止后续派发，账本与预算一致 |

上述验收要求用于本轮实现。构造用例、真实模型/金融工具、浏览器分别记录；实际完成范围及保留边界见核心修复记录，不能互相替代。

完成 A、B、C 后，再进行原第 7 批部署与最终交付。保留原有底座及历史检查结果，同时对新闭环进行回归；测试数量本身不作为 Agent 完成标准。
