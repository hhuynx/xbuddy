## 模型与运行机制

第一次模型调用同时做请求理解和规划，输出 answer、clarify 或 research。一般回答不另外调用金融工具；研究执行后模型读取确定性核验的事实、目标及质量缺口，再决定补取、提问或完成综合回答。正常研究至少需要规划与综合两次模型调用，补充答复、修正和补取后的观察另外计入原预算。

所有新阶段使用原模型调用账本、token 预留/实际 usage、期限、租约、审批和检查点。每阶段最多修正一次，最多一次补取，每 Run 最多三次必要提问；等待输入也计入总时限。答复绑定当前问题、Run 和会话，重复、过期、任意实体候选和跨会话输入不能继续执行。

目标协议限制可用字段，独立证券名称/代码/币种事实必须有解析来源。比较覆盖不能只引用其中一家公司。综合文本禁止模型自行写入实测数值，F 引用必须存在，事实段落只能由核验事实渲染；研究产物再次校验事实指纹、字段、单位、时点与公式。已执行计划编辑后清除旧观察结果，以新版本重新检查目标。

新增业务表通过追加迁移保存消息、Agent 决策和待输入状态。原 checkpoint 与业务数据库保留；本轮没有覆盖用户 .env、默认 data 或 PyCharm 配置。

主要实现：`server/harness/dialogue.py`、`runtime.py`、`model.py`、`reporting.py`，`server/storage/database.py`、`server/api/routes.py`、`server/ui/workbench.py`、`server/exports.py` 和 `server/artifacts.py`。
