本清单拆分自 [完整实现方案](implementation-plan.md)，保持《13_投资XBuddy.md》的全部必需能力和交付物。原计划共 7 批，使用 Python 技术栈，按功能依赖和验收推进。第 1–6 批完成所列底座检查；用户试用暴露的基础交互和综合分析缺口在第 7 批前追加 A–C 修复，当前结果见 [核心修复记录](agent-core-readiness.md)。iFinD 和生产部署仍待验证。历史记录见 [第一批](batch1-readiness.md)、[第二批](batch2-readiness.md)、[第三批](batch3-readiness.md)、[第四批](batch4-readiness.md)、[第五批](batch5-readiness.md)、[第六批](batch6-readiness.md)。

每批都应产出可运行成果、实际验收结果和已知问题，更新 AI 使用与验证记录。测试随功能实现完成，第 6 批集中做跨模块和异常场景验收。

## 第 1 批：接入与环境验证

目标：在写完整产品之前确认研究流程依赖的外部能力。

实施步骤：

1. 检查 Python、Docker 与工作区条件，验证 NiceGUI、FastAPI、LangGraph、SQLite 依赖组合；Node 不作为项目运行前提。
2. 配置模型客户端并验证结构化规划输出，记录响应和耗时。
3. 验证扶摇账号与实际接口，优先检查交易日历、行情、历史 K 线、财务数据；记录权限、字段、单位、时点和复权条件。
4. 如 iFinD 配置可用，发现 MCP 工具并测试与核心场景相关的只读能力；未配置的能力明确保留为未启用。
5. 根据真实能力锁定示例研究范围，确定 2–3 家标的与可获取的数据维度。
6. 验证部署平台可以运行 Python 服务、长连接和持久化卷，避免最终才发现 SQLite 状态无法保存。
7. 确定环境变量名称、依赖锁文件和验证记录格式，凭据只保存在授权环境。

交付物：环境样例、依赖与部署选择、实际能力清单、脱敏接入验证记录、确定的示例目标。

完成标准：模型真实调用成功；至少一个目标金融数据源的真实调用成功；明确场景所需的可用数据和缺口；部署技术路线可行。

异常策略：凭据缺失时继续接口契约、工程和构造响应测试等独立工作；真实接入保持未验证。接口不支持预定场景时调整数据维度，但保留全部 Harness 要求。构造数据不得冒充真实接入成果。

## 第 2 批：工程底座与金融工具

目标：建立可保存、可追溯的研究数据底座。

依赖：第 1 批确认的工具契约与技术栈。

实施步骤：

1. 扩展 server/ui、server/api、tests、docs 结构，将第一批环境页面升级为产品入口。
2. 建立 SQLite 存储及迁移，定义 Thread、Run、Task、ToolCall、Evidence、Claim、Artifact、Approval、Memory 与 Event 数据契约。
3. 实现会话和所属资源权限，确保后续接口与事件按会话隔离。
4. 建立工具注册表和 allowlist，保存输入输出 schema、权限、超时、重试和费用状态。
5. 实现已验证的扶摇 adapters，接入实际可用的 iFinD 工具；同时检查 HTTP 状态和供应商业务 code。
6. 保存原始响应、请求 ID、时间、质量状态和字段映射；正确处理 null、空列表和无权限。
7. 实现历史区间表现、波动率、回撤与财务比较的确定性计算，保存公式及输入证据。
8. 建立持久化事件表、调用账本和幂等键，供后续实时 UI 和恢复使用。

交付物：可启动 API、数据库、工具清单接口、真实数据查询、证据存储和本地计算模块。

完成标准：通过 API 获取并保存真实结果；原始字段与计算结果能互相追溯；单位、时点和口径完整；刷新或重启后数据仍可查询。

## 第 3 批：Agent 研究主链路

目标：让一个研究目标通过后端自动执行到可验证的初版报告。

依赖：第 2 批的数据契约、工具、证据和持久化存储。

实施步骤：

1. 用 LangGraph 定义 Run 状态，接入持久化 SQLite checkpointer。
2. 实现目标解析和 Planner：模型根据目标及可用工具生成任务与依赖，代码验证计划。
3. 实现有限执行循环：调度工具、保存结果、处理质量问题和有限重规划。
4. 每次调用前检查权限、预算、超时与停止状态；重试计入调用预算。
5. 实现审批中断和恢复，审批绑定具体操作、参数和计划版本；批准、拒绝、修改都走服务端验证。
6. 实现后台任务调度、租约、心跳、暂停、停止及重启恢复，客户端连接不承担任务生命周期。
7. 生成最小报告 JSON：结论类型、证据引用、数据缺口、时间和口径。
8. 校验证据存在性、数字与计算、禁止输出表达；不合格核心结论不能正常发布。

交付物：提交研究、查询状态、审批、暂停、继续、停止的 API；完整运行事件；可验证初版报告。

完成标准：示例研究从自定义目标走到真实数据报告；扩大预算能够等待确认；拒绝后不越界；停止后不派发新调用；中断或重启后能恢复未完成节点，已记录完成的工作不重复保存。

阶段展示：即使前端尚未完成，也能通过 API 和事件记录演示完整研究。

## 第 4 批：Web 研究工作台

目标：让用户在浏览器中完成核心研究流程。

依赖：第 3 批的 API、事件和产物契约。

实施步骤：

1. 完成视觉规范和桌面三栏布局，窄屏改为标签页。
2. 左栏实现研究线程、运行状态、新建和历史记录。
3. 中栏实现目标输入、计划展示与修改、任务进度、工具结果和审批卡。
4. 实现暂停、继续、停止与可恢复失败入口。
5. 右栏实现报告、历史图表、财务表、证据抽屉；点击核心结论能看到原始依据。
6. NiceGUI 组件订阅真实持久化事件，通过 Socket.IO/WebSocket 更新；按 event_id 补回断线事件，并通过状态快照恢复界面。事件 API 同时提供 SSE。
7. 增加运行详情、工具配置状态与预算设置；展示费用未知、数据缺失和过期状态。
8. 完成加载、空态、部分结果、失败和等待确认等状态。

交付物：可实际操作的本地 Web 工作台及浏览器流程验证记录。

完成标准：浏览器内从目标到报告完整跑通；审批和任务控制确实改变后端运行；结论可点开证据；刷新或断线后展示真实状态。进度不能由定时动画模拟。

## 第 5 批：上下文、长期记忆与产物

目标：完成上下文管理、跨研究状态和可交付成果。

依赖：第 3 批的运行框架和第 4 批的界面。

实施步骤：

1. 将模型上下文分层，大型工具响应保存在文件/记录中，通过证据 ID 按需读取。
2. 实现按上下文预算触发的压缩，摘要保留目标、约束、口径、任务状态、审批、证据 ID 和未解决问题。
3. 保存摘要与原文范围，增加压缩前后估计、触发原因和真实压缩事件。
4. 实现结构化记忆的保存、检索、删除、修正和过期标记；推断的个人偏好写入前等待确认。
5. 新研究显示实际使用的记忆，有效研究事实仍保留来源与时间边界。
6. 完善事实、推断、不确定信息的呈现与校验。
7. 完成版本化报告、Markdown/HTML、CSV 与证据索引导出；支持浏览器打印到 PDF。
8. 追问触发新的 Run 并连接已有研究，按时效重新获取需要更新的数据。

交付物：真实压缩机制、记忆服务和管理界面、版本化产物与导出。

完成标准：压缩后关键口径和引用保持完整；新研究使用有效记忆、删除后不再使用；产物版本能追溯到 Run 和证据。这证明上述运行机制，不证明研究 Agent 的交互、观察和综合回答完整；相关缺口见基础能力复核。

## 第 6 批：异常、边界与整体验收

目标：验证整条链路在失败、极端与合规场景下的行为，并修复影响交付的问题。

依赖：第 2–5 批全部功能；这些批次随开发完成的模块检查继续保留。

实施步骤：

1. 主链路 E2E：目标、规划、工具、计算、证据、报告、追问和导出。
2. 数据故障：HTTP 200 但业务失败、null、空列表、超时、限流、权限不足、过期和多源冲突。
3. 金融口径：交易日不一致、复权未知、单位不明、除零、负利润、极端价格、财务报告期/累计单季混用。
4. 模型故障：结构错误、虚构证据、报告失败、摘要失败以及来自新闻/文档的提示注入。
5. 运行控制：预算耗尽、重规划上限、重复审批、参数变化后旧审批失效、暂停和停止。
6. 状态恢复：页面断线、SSE 补传、服务中途重启、审批等待期间重启及已完成调用的账本复用。
7. 跨研究记忆、记忆删除、压缩后的约束与证据完整性。
8. 产品表达：确定性预测、收益承诺和直接买卖建议请求的处理；事实、推断和不确定信息的区分。
9. 会话资源隔离、日志脱敏和公开仓库数据检查。
10. 写入真实测试结果，修复关键失败，未执行或未通过项目如实记录。

交付物：单元/集成/E2E 测试、测试说明、人工抽查记录、问题修正与复验结果。

完成标准：关键主链路和必需边界检查通过；无法满足的部分清晰标注；失败不会静默生成正常结论；恢复确实从持久化状态继续。

构造响应用于可重复故障测试；真实金融源另有授权集成验证，两类记录明确区分。

## 第 7 批：部署与交付

目标：完成可访问产品及全部必交材料。

依赖：第 6 批已有检查通过，且基础能力补齐 A–C 的用户任务验收通过；部署路线已选择，实际平台运行条件仍需验证。

实施步骤：

1. 构建 Python Docker 镜像，NiceGUI 与 FastAPI 同源运行。
2. 配置 HTTPS、环境变量、持久化卷和公开演示配额，确认重启保存状态。
3. 在授权部署环境启动产品，验证外部浏览器的访问、真实研究、UI 长连接、SSE API、审批与恢复。
4. 完成源码仓库、依赖锁文件与 .env.example，检查 API Key、隐私和受限数据。
5. 完成 README：启动、环境变量、产品选择、AI 角色、数据源、边界和未做事项。
6. 整理随开发积累的 AI 使用、实际错误、人工修正与验证记录。
7. 完成 testing.md 与 known-limitations.md，写明真实运行条件和结果。
8. 如有余量，录制一名用户完成核心研究的 60–180 秒演示视频。

交付物：可访问且可操作的 Web URL、源码仓库 URL、README、AI 使用与验证记录、测试说明；演示视频可选。

完成标准：外部用户能够实际完成核心任务；按 README 可以启动源码；全部必交材料齐全；记录中未将计划或未验证能力写成已完成。

## 每批完成后的报告格式

- 已完成：本批可运行能力及对应文件。
- 如何验收：可执行命令、浏览器路径或 API 操作。
- 实际验证：通过/失败结果、关键证据。
- 未完成与影响：外部依赖、功能边界及对下一批的影响。
- 下一批：即将实现的能力与依赖。

批次是开发与验收边界，不要求每批额外增加一次用户批准。需要用户信息的外部依赖及会改变范围的选择应及时提出，其余已授权工作继续推进。

## 实现优先级

优先保证一个真实研究场景贯穿全部必需机制。iFinD 扩展、额外图表、其他市场、多角色 Agent 和视觉完善按产品需要安排，演示视频可选。工具注册、规划执行、压缩、记忆、检查点/恢复、审批/停止、成本/时延/观测、证据、动态 UI、异常处理以及全部必交材料均保留。
