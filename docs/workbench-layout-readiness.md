# 工作台布局改进 · v0.8.0

日期：2026-10-11。针对用户反馈的历史对话定位困难、左右同时阅读拥挤，以及提问、回答和证据混排，已实现单一主工作区。保留 Python/NiceGUI 技术栈和原 Agent 的权限、审批、检查点、证据及产物流程。

## 页面和交互

- 左侧研究列表可收起；手机端用菜单展开。主区统一提供“对话 / 研究报告 / 研究过程”，新建或切换研究默认进入对话，刷新恢复上次选择的运行和视图。
- 用户提问使用右侧浅色气泡；XBuddy 回答使用左侧头像、名称、时间和 Markdown。知识回答直接显示并注明未查询本次金融数据；研究回答取已校验报告的前三个分析/不确定性段落，附编号引用与“查看研究报告”。
- 对话单独滚动，输入区固定在主区底部。进入时定位最新内容；正在向上阅读时保留位置，新回答提示“有新消息”；点击“回到最新”恢复跟随。追加消息保留已有组件，避免每次事件重绘整段对话。
- 首屏最近 20 条；“加载更早的对话”向前分页并保持可见内容的位置。API 支持 `before` 与 `limit`，返回 `messages / has_more / before`。分页保留所属会话和内容指纹校验；模型依然只使用最近 60 条，不扩大模型调用预算。
- 输入区支持 Ctrl/Cmd + Enter 发送，Enter 换行并避开输入法组合状态。页面内切换研究保留草稿，切换旧运行不把旧目标重新塞进输入框。澄清和预算审批放在对话末尾，可在原 Run 继续。
- 报告使用完整主区宽度，保留版本、图表、财务表、追问和导出；全部核验事实、原始来源及其他细节默认折叠。正文中准确匹配已引用事实的数字采用可读的亿元/百分比显示，保留标的和年度；原始数值、已保存报告和导出不被改写。任务计划、预算消耗、事件、上下文和手动查询集中在研究过程。
- 点击引用打开绑定原报告版本的证据。抽屉先展示支持的事实、原始值/单位、来源和所选报告期/披露日期；字段路径、JSON、映射校验及公式按需展开。

历史数据与报告的生成规则保持原版本。此次页面改进可查看现有记录，无需为更换布局重新调用模型或金融源；v0.7.1 多年度修复所要求的新运行复验仍见其独立记录。

相关回归首次为 59 passed / 2 failed；两项失败属于新分页测试准备：使用错误的运行模式、未初始化第二个匿名会话。修正准备后两项通过，所有权限和完整性断言保留。浏览器首次发现非当前 Run 的新消息没有更新，以及澄清后回调仍使用已删除卡片上下文，分别修正事件刷新和页面根客户端调用。其余探测失败来自隐藏页面同名标签、操作后未等到渲染完成，以及点到手机抽屉覆盖的遮罩中心；改为等待实际面板/原字段、限定选择器并点击露出的遮罩。Windows 浏览器连接关闭偶发 `Proactor WinError 10054` 日志单独记录，页面未捕获错误为 0。

数值展示调整后再次复验时，并行浏览器/pytest 出现两次等待超时：消息检查的失败快照已经包含新回答，SSE 检查在二十秒等待结束后事件已有完整报告和 `run.finished`。后续分开复验，保留原完成状态、消息数、SSE ID 和预算断言；不将超时记录删除或记作通过。

## 本地复验

```powershell
& .\.venv\Scripts\python.exe -m pytest tests/test_agent_core.py tests/test_workbench.py tests/test_financial_history.py tests/test_knowledge.py tests/test_message_pages.py -q
& .\.venv\Scripts\python.exe scripts/smoke_ui.py
```

浏览器检查需要可选 QA 工具 Node、Playwright Core 和 Edge，不增加生产运行依赖。在独立终端启动构造服务器：

```powershell
$env:XBUDDY_QA_DATA_DIR = Join-Path (Get-Location).Path '.cache\verification\workbench-layout-local'
$env:XBUDDY_QA_PORT = '8107'
& .\.venv\Scripts\python.exe scripts/agent_core_fixture_server.py
```

另一个终端运行 `node scripts/verify_workbench_layout_browser.cjs`。默认检查 `http://127.0.0.1:8107`；可通过 `XBUDDY_QA_BASE_URL` 指定实际隔离服务器。Playwright Core 未在 Node 搜索路径时，将 `XBUDDY_PLAYWRIGHT_CORE` 设为已有包的绝对目录；Edge 路径不同则设 `XBUDDY_BROWSER_PATH`。脚本仅对构造服务器发请求，结束后停止该测试服务器。

## 用户查看

PyCharm 停止旧的 `server.main` 运行，再按原配置启动并刷新浏览器。新布局默认打开最新对话；点“查看研究报告”或主区标签查看完整成果，点引用看依据。`.env`、PyCharm 运行配置及默认 `data` 未被此次验证覆盖；用户原 8080 服务由用户重启以加载新代码。
